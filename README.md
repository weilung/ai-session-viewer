# AI Session 對話檢視器

把 Claude Code CLI 的 session 紀錄（`~/.claude/projects/<專案>/<sessionId>.jsonl`）與 Codex session 紀錄
（`~/.codex/sessions/**/*.jsonl`）轉成
方便「翻閱」的 **HTML** 與方便 grep／存檔的 **Markdown**。零外部相依，只用 Python 3 標準函式庫，
**跨平台**（Windows / Debian / macOS），並支援**多個 Claude 帳號**與 Codex 來源。

> ### ⚠ 這兩塊的審查狀態
>
> **Codex 使用者回合的解析**與**快取失效成因歸因**這兩塊，跨模型 code review **尚未收斂**。
> 照實揭露，讓你自己判斷要不要依賴這兩塊產出的數字：
>
> | | |
> |---|---|
> | 跑到哪一步 | 已跑到這套流程的**最高一層**（跨廠商、最強型號的獨立審查），共 5 道；另有 6 道同一家族模型的獨立審查（換脈絡，不等於跨廠商）|
> | 這塊的天花板 | 就是那一層——沒有更高的可跑 |
> | 會不會被實際執行 | 會（Python 產品碼）。每一道審查都真的跑起了完整測試套件，全部通過 |
> | 收斂了嗎 | **還沒**——每一道都仍列出待處理項目，且最高那一層仍在冒出前幾道沒有的類別。已列出的項目都已處理或登記，但「處理完」不等於「收斂」|
> | 修正本身可靠嗎 | **也要打折。**後續每一道審查都會在**前一道的修正**上再找到東西：有些是修正新造的問題（最近一次讓報告的某一整個章節靜默消失，而測試全數通過），有些是「修對了、但只涵蓋了一部分情況」（例如某個防呆只在最常見的路徑上生效）。後者不會讓任何測試變紅，所以**「這一格修過了」不等於「這一格沒問題了」**|
>
> 已知且已被接受的偵測範圍限制見下方〈**偵測的限制**〉。其餘功能（HTML/Markdown 轉換、
> 搜尋、索引、成本統計等）不在這個範圍內。

## 快速開始

Windows（PowerShell）：
```powershell
py ai_session_viewer.py            # 全部帳號/專案 -> .\out，同時輸出 HTML + Markdown
py ai_session_viewer.py --open     # 轉換後自動打開 out\index.html
py ai_session_viewer.py --no-codex --open      # 只轉 Claude（預設會連 ~/.codex 一起轉）
```
或直接**雙擊 `run.cmd`**。

Debian / macOS：
```bash
python3 ai_session_viewer.py --open
# 或： chmod +x run.sh && ./run.sh
```

打開 `out\index.html`：session 索引，可用**關鍵字搜尋**與**專案／月份／型態下拉**交叉篩選，
點欄位標題可排序，右側顯示符合筆數；點標題進入單一對話。
「型態」是自動分類：`review`（首句是 review prompt，`# Review` 開頭——跑 cross-model review 的人適用）、
`exec`（Codex 無頭執行 `codex exec`，取自 session_meta）、其餘為一般互動；review/exec 會在標題旁
與對話頁標記。看快取／成本統計時建議分開看——這兩類與互動 session 的快取行為是不同母體。
（全部同一型態時不會出現此下拉。）
HTML 把工具呼叫、思考、子代理對話都做成**可摺疊**區塊，預設收合，閱讀時不被雜訊淹沒。
若某 Claude 專案有 memory，索引與對話頁會出現 🧠 入口連到該專案的 memory 頁（見〈專案 memory〉）。

## 常用參數

| 參數 | 說明 |
|------|------|
| `--claude-source <路徑>` | 輸入的 Claude `projects` 目錄，可**多次指定**，亦可寫成 `標籤=路徑`；覆寫自動偵測 |
| `--account <名稱>` | 捷徑：等同 `--claude-source 名稱=~/.claude-名稱/projects`（預設帳號用 `--account default`） |
| `--codex-source <路徑>` | 指定 Codex `sessions` 目錄或單一 JSONL，可多次指定，亦可寫成 `標籤=路徑`；覆寫自動偵測 |
| `--no-claude` | 不讀取 Claude Code 紀錄 |
| `--no-codex` | 不讀取 Codex 紀錄（預設會自動偵測 `~/.codex/sessions`） |
| `--out <路徑>` | 輸出資料夾（預設 `./out`） |
| `--format html\|md\|both` | 輸出格式（預設 `both`） |
| `--project <字串>` | 只轉名稱含此字串的專案，例如 `--project Obts` |
| `--include-empty` | 連同**完全沒有回合**的空 session 一起輸出。⚠ 只有指令、沒有對話的 session **不算空**（指令現在會畫出來），要處理那種請看 `--archive-command-only` |
| `--force` | 忽略快取，全部重新產生 |
| `--open` | 完成後自動打開 `index.html` |
| `--archive-command-only <目錄>` | 把**只有指令、沒有對話**的 Claude session 的 JSONL **搬到**該目錄（檔名＝`<munged cwd>__<原檔名>`），並刪掉它產生的頁。⚠ **會動到 `~/.claude/projects/`**，詳見〈整理只有指令的 session〉 |
| `--search "詞…"` | 全文搜尋既有輸出的**對話內容**，產生可點擊跳轉的結果頁（見〈全文搜尋〉）；搭 `--open` 直接打開 |

## 多帳號 / 多工具來源

呈現多個來源的通用方式就是**指定輸入目錄與輸出目錄**：用一個或多個 `--claude-source` 指向各自的 `projects` 目錄，
輸出到同一個 `--out`。索引頁會多一個「帳號」欄與下拉篩選，各來源的輸出會依工具與帳號分開，
Claude Code 會放在 `out/sessions/claude-code/<標籤>/`，Codex 會放在 `out/sessions/codex/<標籤>/`。

```bash
# 明確指定多個來源（適合作業系統多使用者、或紀錄放在非預設位置）
python3 ai_session_viewer.py \
  --claude-source main=~/.claude/projects \
  --claude-source work=~/.claude-work/projects \
  --out ~/ai-logs --open
```

只轉 Codex（停掉 Claude 即可，Codex 預設自動偵測）：

```bash
python3 ai_session_viewer.py --no-claude --out ~/codex-logs --open
```

未加任何來源參數時，**Claude 與 Codex 都會自動偵測**：`~/.claude*` 下所有含 `projects` 的目錄、以及 `~/.codex/sessions`（沒有 `projects` 子目錄的、
例如某些第三方工具的設定夾，會自動略過）。若你的多帳號剛好是 `~/.claude` 與 `~/.claude-<名稱>` 這種命名，
也可以用捷徑 `--account <名稱>`。

> **關於多帳號與 `--account`：** Claude Code 沒有官方的多帳號功能，常見做法是進 CLI 前先設
> `CLAUDE_CONFIG_DIR` 指向另一個設定資料夾（例如 Windows `set CLAUDE_CONFIG_DIR=%USERPROFILE%\.claude-work`、
> Unix `export CLAUDE_CONFIG_DIR=~/.claude-work`），各帳號的 `projects` 就分屬不同資料夾。
> `--account work` 只是「`~/.claude-work/projects`」的捷徑，**前提是你的設定夾照 `~/.claude-<名稱>` 命名**；
> 若 `CLAUDE_CONFIG_DIR` 指到其他位置（例如 `D:\foo`），請改用 `--claude-source work=D:\foo\projects`。

## 增量建置（只重產有變動的）

每次產生會在 `out\.build-manifest.json` 記錄每個 session 來源檔的指紋（mtime + 大小，含外部子代理檔）。
下次執行時只會重產**有變動或新增**的 session，其餘直接沿用既有輸出；索引頁每次都會重建（很快）。
已刪除的 session 其輸出檔會自動清掉。完成訊息會顯示「新建/更新 N、沿用 M」。

- 要強制全部重來：加 `--force`。
- 局部重產（`--project` / `--account` / `--claude-source`）時，不會動到也不會誤刪其他範圍的既有輸出。

## 整理只有指令的 session

開了視窗、設一下 `/model` 或 `/effort`、看個 `/context` 就離開——這種 session 沒有任何對話，
但指令現在會畫出來，所以它們**不算空**、會出現在索引頁上。

要把它們挪開：

```bash
py ai_session_viewer.py --archive-command-only D:\path\to\封存目錄
```

它會把那些 session 的 JSONL **搬到**指定目錄，並刪掉它們產生的 HTML／MD。

⚠⚠ **這是本工具唯一會動到 `out/` 以外檔案的功能，只有明確給了這個參數才會發生**
（不給就連判定都不做）。動到的是 `~/.claude/projects/`，也就是 **Claude Code 自己**在讀的目錄
——被搬走的 session **不會再出現在 `claude --resume` 的清單裡**。

怎麼保證不會搬錯、以及搬錯了怎麼救：

- **判準直接讀渲染管線的產物**，所以「會被搬走」的定義就是**「頁面上除了指令列什麼都沒有」**。
  只要有任何使用者發言、助手回覆、工具呼叫、貼圖，就算對話，不會被搬。
- **每一筆都記進該目錄的 `_archived.jsonl`**，含**原始絕對路徑**、cwd、帳號、時間、判定理由。
  還原不必靠人記得檔名怎麼組。
- 檔名是 `<munged cwd>__<原檔名>.jsonl`（把 cwd 的 `:` `\` `/` 換成 `-`），一眼看得出它本來在哪。
- 四道安全閘：封存目錄不可以在來源目錄裡面、不可以是來源的上層、不可以在 `out/` 裡面、
  **絕不覆蓋**同名檔（撞名就略過並保留原檔）。子代理目錄跟著一起搬。

## 它怎麼處理紀錄

- **依時間排序**呈現，並把新版格式中被拆成多筆事件的 assistant 回合（thinking / 文字 / 工具）
  併回單一回合；工具的輸出會附在對應的工具呼叫底下。
- 過濾掉 `/指令`、本機指令輸出、系統提醒等雜訊；只有這些內容的 session 預設不輸出。
- **專案命名**：以 Claude 的 munged 夾（`~/.claude/projects/<munged-cwd>/`）為單位，**一夾一專案名**，
  顯示名取自該夾「原生 cwd」的葉名。專案搬遷後把舊夾 session 複製進新夾，舊 session 也會歸到新專案名底下；
  單頁仍如實顯示它當時的 `cwd／帳號／夾`，不抹掉歷史。
- 標題優先序：你用 `/rename` 設的名稱（索引以 ✎ 標示，並把 AI 自動標題列為輔助小字）＞
  AI 自動標題（`ai-title`）＞ 第一句使用者訊息。
- 顯示每個 session（與每一則）用到的**模型、估算花費、快取命中率、脈絡/產出 token**（見下方〈成本與快取〉）。
- 訊息或工具結果中的**內嵌圖片**（base64）會以 `<img>` 呈現（超過上限只放佔位）；
  Markdown 連結只允許 http/https/mailto/相對/錨點等安全 scheme，其餘降為純文字。
- 子代理（subagent）對話：同檔內的 `isSidechain` 事件、或外部
  `<sessionId>/subagents/*.jsonl`，都會收進該 session 的「子代理對話」摺疊區。

## 成本與快取（估算）

很多人搞不清「這段對話有沒有命中快取、花了多少」。本工具把它算給你看：

- **索引頁**：每個 session 一欄「估算$」，頁頂顯示**估算總花費**；另有一欄「**浪費**」與標題旁的
  🔥 徽章，標出該場**人因可避免**的快取浪費（見下方〈哪些快取沒命中是你自己造成的〉），
  可點欄頭排序，並用「只看有人因浪費的」勾選框篩出來。
- **單一對話頁**：頁頂有「💲估算花費 · ⚡快取命中% · 脈絡峰值 · 產出」；每一則 assistant 還有可勾選的小徽章
  （⚡快取% / **⚠失效原因** / 💲花費 / **新輸入 / 快取寫入 / 快取讀取** / 脈絡 / 產出 /
  **距上一步 / ⏱耗時 / effort**，預設顯示快取、失效原因與花費，其餘按需勾開，勾選狀態記在瀏覽器）。
  「新輸入 / 快取寫入 / 快取讀取」就是把單一 token 量攤成四種來源，想細看某輪吃了多少
  快取、寫了多少新快取時很有用；「脈絡」在知道該模型視窗時會附**佔視窗 %**（離自動壓縮還有多遠）。
- **Markdown** 也會在 session 表頭與每則標題附上同樣資訊。

**⚠失效原因（Claude 自報，不是我們猜的）**：2026-05 起的 Claude Code 會在
`message.diagnostics.cache_miss_reason` 直接寫出這次為什麼沒命中——工具定義變動／系統提示變動／
前文內容變動／換模型／前文不在快取／快取暫時不可用，部分還附**「失效前綴有多長」**
（從多久以前的內容開始對不上，**不等於這次重寫了多少**——實測有回報 344k、該步卻只寫入 8k 的），
本工具據此標出成因，並以該步實際寫入量為上限估算多付了多少錢。兩件事因此看得見了：

- **前四種不是「快取失效」**，是你把前綴改掉了（載入 MCP/skill、改 CLAUDE.md、倒帶重編）——
  一定會重寫，跟離開多久無關；徽章標中性灰，也不列入 TTL 統計。
- **部分失效**：命中率還有 9 成、卻有一段被迫重算（分母同步變大，`⚡%` 完全看不出來）；
  這種只有徽章與報告的「②-b」看得到，標成中性的「部分失效」以免與整段冷啟混淆。

怎麼算的（重要）：JSONL 只記 **token 數、不記金額**。金額是**估算**——各模型單價 ×（快取讀取 0.1×、
寫入依 TTL：5 分鐘 1.25×／1 小時 2×）。新版 JSONL 的 `usage.cache_creation` 物件會記兩種 TTL 各寫多少，
工具逐筆精算；舊資料沒有細分的部分按 5 分鐘估（若實為 1 小時會低估）。價格表在程式頂端 `PRICE_PER_M`，
會隨官方調價變動，需要時自己改即可；未知模型只計已知部分並標 `+?`，內部偽模型 `<synthetic>` 視為不計費。

> 名詞：`input`=未命中快取的新輸入；`cache_read`=從快取重用（長對話每輪都重讀整段脈絡，故總量很大）；
> `cache_creation`=寫入快取；「脈絡」≈ 單輪 input+cache，約等於「重開這個 session 第一句要重讀多少」。

**逐步快取命中率**：一個 assistant「回合」常是一次提問內連續呼叫多次 API（思考→工具→再思考…）。
多步回合會在每步開頭標出**該步**的 ⚡快取% / 脈絡 / 產出，看得到快取從第一步到最後一步逐步升溫
（沿用同一組勾選開關）。Claude 依 message.id 切步；Codex 依每次呼叫的 token_count 切步——
冷啟動的那一步不再被回合彙總平均掉。

**冷啟不再一律標紅（區分「本來就不會命中」與「真的把快取弄丟」）**：低命中的步驟會沿用健檢報告的
成因判定分兩級著色——**真失效**（閒置過期、自行切帳號、1 小時內異常提早失效）才紅底白字；**結構性、本來就不會命中的**
（session 首呼叫全新前綴、回合內快取斷點的一次性 miss、換模型、壓縮後、撞 limit 被迫切帳號）改中性灰並在滑鼠提示寫明
成因，避免被誤讀成「快取一直失效」。這解答了「為何第一輪有時冷、有時不冷」——若前一個 session 剛跑過、
系統前綴（約 1.7 萬 token、1 小時 TTL）還熱，首呼叫就會直接讀到而不冷；熱度過了才冷，且那種冷是結構性的。
成因分析只套用在 **Claude 主對話**（與健檢報告同源、有一致性測試釘住）；Codex 與子代理不做分析，其冷啟維持原標示。

## 哪些快取沒命中是你自己造成的

大部分冷啟你無能為力（首呼叫、換模型、壓縮、改了 CLAUDE.md）。真正**改習慣就能省**的只有兩種，
工具把它們單獨挑出來，索引一欄「浪費」＋🔥 徽章、報告一個「人因浪費」KPI，兩邊同一個口徑：

- **閒置過期**——離開太久才回來，快取 TTL 已經過了。
- **自行切帳號**——**沒撞 limit 就換帳號**。快取按 organization 隔離（Claude API 上另外還按 workspace 再隔一層），換帳號等於把整段前綴丟掉。

第二種以前看不見：自願切換不會留下 429/401，session 紀錄裡也沒有任何欄位標示帳號，那一步只會被
看成「1 小時內卻冷啟」而歸進**提早失效**（伺服器側異常）。本工具改從各帳號 config 目錄各自的
`history.jsonl`（記 sessionId ＋ 時間）比對：同一個 sessionId 出現在兩個帳號＝那場中途換過帳號。
作者本機實測 19 場、23 個切換邊界，其中 21 個下一步就是冷啟；重新歸類後「提早失效」少掉 38%
——原來那些不是異常，是自己切的。

**偵測的限制（工具不會假裝它是完備的）**：

- 只有**同一台機器上有多個帳號**時才偵測得到；單帳號的話這個成因永遠是 0，其餘功能不受影響。
- `history.jsonl` 是**本機**狀態。跨機同步過來的紀錄，另一台發生的切換這裡看不到。
- 同一列若被複製到另一個 config 目錄（手動同步、備份還原），會被視為無法歸屬而**排除**，
  寧可漏報也不會誣賴你切了帳號。
- **撞到 limit 之後才換帳號，有可能仍被算成「自行切帳號」**（也就是算進人因浪費的金額裡）。
  判斷「被迫還是自願」時，只看得到**相鄰兩次呼叫之間**發生的事；429 與換帳號中間只要夾了
  任何一次呼叫，兩者就被拆到不同區間、對不起來。發生這種情形時，該步的徽章會把
  **「同場稍早撞過 limit」與「自行切帳號」兩個條件並列標出**，報告的說明段也會寫出有幾次
  ——金額仍算在「自行切帳號」那一邊，**要不要採信由你自己判斷**。
- 只讀 `sessionId` 與時間戳，**不讀 `history.jsonl` 裡的 prompt 內文**。
- **config 目錄不在 `~/.claude*` 樣式底下時，涵蓋率會下降**：那種佈局要靠 `--claude-source`
  指定來源，而 config 清單是從來源清單推導的；若多個帳號的 `projects/` 是指向同一實體的
  junction／symlink，它們會被收斂成一個，那些帳號之間的切換就偵測不到（顯示 0 次，無錯誤訊息）。
  **預設佈局（`~/.claude`、`~/.claude-<名稱>`）不受影響。** 這是已知且目前接受的限制。

**「提早失效」刻意不算進人因浪費**：那是伺服器側的異常，不是你控制得了的事。

## 快取分析報告

命中率常常一冷一熱，看單則不容易看出規律。`out/cache-report.html`（index 頂有連結，有可分析的 Claude
相鄰步驟/長閒置資料時才產生；報告頂端「涵蓋範圍」會標出本次納入的 session 與日期區間——縮範圍建置時就是該子集）
把這些 session 的逐次呼叫拿來統計：

- **總覽 KPI**：整體命中率（token 加權）、**TTL 遵約率**（1 小時快取、閒置 2–55 分內回來仍命中的比率——
  距 100% 的缺口就是「提早失效」）、**人因冷啟**次數與**估算人因浪費**（與索引「浪費」欄同口徑）。
- **快取能撐多久（TTL 存活曲線）**：拿同一 session 內相鄰兩次呼叫的「間隔」對上「下一步是否冷啟」，
  畫成命中率曲線（log 間隔軸、附 Wilson 95% 信賴區間），並依 `usage.cache_creation` 的 TTL 細分把
  「1 小時寫入」與「TTL 未知（舊資料）」分開兩條看；閒置超過 1 小時仍命中的**異常存活**另列清單。
- **冷啟成因分解**：每個冷啟恰好歸一個成因——session 第一句／**limit·被迫切帳號**（自動偵測 429/401 邊界；
  快取按帳號隔離，切帳號後第一步必冷啟）／換模型／**工具定義變動·系統提示變動·前文內容變動**（Claude
  自報）／壓縮後／閒置過期／**自行切帳號**（沒撞 limit 就換，見〈哪些快取沒命中是你自己造成的〉）／
  **提早失效**（1 小時內就失效的異常）／回合內雜訊——做成分週堆疊圖。
  **有 API 自報就以自報為準**，沒有才用間隔推論；結構性成因（含前綴變動）不會混進 TTL 統計。
  另有「**②-b Claude 自報的失效成因**」一節，把冷啟與**部分失效**（命中率仍高、卻有一段被重算）
  一起列出，附 API 回報的**失效前綴長度**（不等於這次重寫量）與估算多付的金額
  （金額另以各步實際寫入量為上限）。
- **你都什麼時段重新暖機**：「閒置 ≥ 30 分後、確實冷啟的第一步」做成 24 小時直方圖、平日／假日分開、
  正規化為**次/活躍日**；每根 bar 拆「可避免（實色）／非閒置造成（淡色，含前綴變動）」兩段。
- **假說檢定頁**（`out/cache-hypotheses.html`，與報告成對產生、互相連結）：把「提早失效」的候選成因
  一個假說一節逐一檢定。樣本一律取 1 小時快取「應命中帶」（閒置 2–55 分）的相鄰步驟，依間隔分層做
  CMH 勝算比檢定（先控制「午休/夜間本來就閒得久」的混雜）、樣本不足會直說——方便你拿自己的 JSONL
  跑出同一組統計，跟別人的結果對照。**能歸給「前綴被改掉」的（API 自報）已從樣本剔除**，
  這頁追的是剩下沒有已知解釋的失效：
  - **伺服器時段假說**：依 **UTC（伺服器時間）**看各時段提早失效率（dot plot＋信賴區間），檢定
    「全球尖峰（13–21 UTC）是否較易失效」。
  - **累積脈絡假說**：依前一步脈絡大小分箱看失效率（附 Cochran–Armitage 趨勢檢定），並以帶內中位數
    切大/小脈絡檢定「context 越大是否越容易被擠掉」；另附失效當下形態的機制線索（是否整段重寫、
    殘餘命中量）。
- **什麼時候撞到 limit**：附帶統計 429 撞牆時刻的分佈。

純估算、只統計 Claude 主對話（子代理／Codex 不納入）；健檢頁③④時間用本機時區、假說頁①用 UTC（伺服器
時間）。資料存在每個 session 的 manifest row 裡，所以增量建置不必重讀 JSONL 就能更新報告。

**Codex 呢？**兩家 TTL 機制不同（OpenAI 是自動快取：無寫入量/TTL 標記、前綴部分命中、快取在組織內
跨 session 共享），所以 Codex **不混進上述統計**，另出獨立頁 `out/cache-codex.html/md`（有 Codex
資料時產生、index 頂有連結）：相鄰呼叫的「閒置間隔 → 命中率」存活曲線，依 session 型態
（review／exec／一般）分層對照，附短間隔斷點雜訊率、各間隔桶的中位命中%（看部分命中的衰減幅度）與
長閒置仍命中的觀察清單。頁上明示方法限制：這是**觀察**，不是 TTL 量測——長閒置後的「命中」可能只是
共享前綴殘餘或其他 session 恰好刷新。

## 專案 memory

Claude Code 的 **memory**（`~/.claude/projects/<專案>/memory/`：`MEMORY.md` 索引＋每則一個 `.md`、含 frontmatter）
會被整理成**每個專案一頁**的檢視（`out/memory/claude-code/<帳號>/<munged專案名>-<hash>.html`）：`MEMORY.md` 當總覽，
每則事實做成一張卡（type 標籤＋描述＋渲染內文；`[[name]]` 與 `MEMORY.md` 內的連結都轉成同頁錨點，點了就跳）。

三個入口，**只有該 Claude 專案真的有 `memory/` 時才出現**：

- **索引下拉**：在「專案」下拉選到該專案時，表格上方浮出 🧠 面板連到它的 memory 頁。
- **索引每列**：屬於該專案的每個 session 列尾有一個 🧠。
- **對話頁頂**：每頁左上「← 回索引」旁有「🧠 專案 memory」。

只有 Claude 有這種 memory（Codex 無，所以「選 Claude」是天然條件）；memory 頁每次重建，並清掉已不存在專案的孤兒頁。

## 全文搜尋

索引頁的搜尋比對 標題／專案／cwd／夾(munged)／帳號／分支 等欄位（所以搬遷前的舊路徑或舊專案名仍搜得到）。
要搜**對話內容**，用內建全文搜尋：

```bash
py ai_session_viewer.py --search "關鍵字" --open            # 空白分隔多詞 = 同一則訊息內全部命中（AND）
py ai_session_viewer.py --search "快取 OR cache"            # 獨立大寫 OR = 任一命中；A B OR C ＝ A 且 (B 或 C)
py ai_session_viewer.py --search "'cache read' 命中"        # 引號包片語（單雙皆可）逐字比對，片語內空白可跨換行
py ai_session_viewer.py --search readme --match-case        # 區分大小寫（預設不分）
py ai_session_viewer.py --search "關鍵字" --project Obts    # 縮範圍：--account / --no-claude / --no-codex 同理
```

沒有 `AND` 關鍵字——空白就是 AND；要搜「OR」這個字面詞就用引號（`"OR"`）。

它直接掃既有輸出的 `.md`（所以要**先跑過一次轉換**；工具輸出、思考內容都搜得到），把命中做成一頁結果
（`out/search/<時間>__<關鍵字>.html`）：依 session 分組、顯示高亮片段，**點任一筆就開該對話頁並跳到命中的那一則**
（命中在收合區塊或子代理對話內會自動展開），頁內另有再過濾框。結果頁會留存方便回頭看，
每次搜尋時自動清掉超過 30 天的舊結果頁。

離線／進階仍可 `rg "關鍵字" out/`（或 VS Code 全域搜尋）：`.md` 每則訊息標頭帶有 `{#t12}`（子代理為 `{#s3}`）
錨點標記，把它接在同名 `.html` 後（`….html#t12`）就能開瀏覽器直接跳到那一則。

## 書籤

每一輪對話的標頭右邊有兩顆小東西（滑過該輪才顯形）：

- **`#`**：這一輪的**直達連結**。網址長這樣 `….html#k20260801T025233123Z` ——
  那串 `k…Z` 是該輪的 UTC 時刻（毫秒），存進瀏覽器「我的最愛」就能直接跳回來。
  ⚠ 用時間戳而不是序號，是因為**序號會漂**：解析器只要多切出一輪，其後全部往後推一格
  （實測四週內有 6 輪這樣位移），而時間戳一輪都沒漂。
- **`☆`**：加書籤。可以寫**備註**、給**類別**、選**提醒我複查**的間隔（預設半年）。
  已加過的那一輪會固定顯示實心 `★`。
  類別是一排可點的 chip，最後一顆固定是「**＋ 新類別**」——現場想到新類別，
  按下去就地打字、Enter 建好並選起來，**全程不用離開這個小視窗**。
  類別多的時候預設只露出最近用過的幾個，後面接一顆「更多…」。

頂列的「🔖 書籤」會顯示這一頁存了幾筆、幾筆該複查了，點開可以列出、跳轉、編輯、
只看該複查的，以及**匯出／匯入**。

### 也可以只標一個區塊，不必標整輪

同一組 `#`／`☆` 在**每一個區塊**上也有一份——某一則工具呼叫、某一段回覆文字、
某一段思考——一樣是滑過那一塊才顯形。用途是「跳回那則 `Bash`」而不是「跳回那一輪」：
一輪裡放上百個區塊是常態（本機語料實測，Claude 側每百輪有 13 輪、Codex 側有 34 輪
超過 20 個區塊，最長的一輪 412 個），只能標到「輪」的話等於只能跳到那段對話的開頭。

區塊的網址長這樣 `….html#k20260801T025233123Z-s1785000123456-b2`：
`k…Z` 是那一輪、`-s…` 是那一次 API 呼叫的起始時刻（**epoch 毫秒**）、
`-b2` 是那次呼叫裡的第 2 個區塊。

⚠ **區塊層級的連結沒有「輪」那麼耐久，這是刻意的取捨。** `-b2` 是序號，
解析器改版時有可能位移。但它的作用域被關在**一次 API 呼叫之內**（實測那裡只有 1〜4 個
區塊），而不是整輪；而且**找不到時會一段一段往回退**——先退到那次呼叫、再退到那一輪，
並明講「原連結指向這一輪裡更細的位置，那個位置在這份輸出裡找不到」。
**不會安靜地跳到別的地方。**

**索引頁**（`out/index.html`）的每一列，只要那場有書籤就會在標題前面出現 `🔖`
（多筆帶數量、有到期的帶 `⏰`，游標停留可看筆數與類別），
篩選列另有一顆「🔖 只看有書籤的」——一場書籤都沒有時它不會出現。

**到期只是一個標記，書籤永遠不會自動刪。** 到期的那幾筆在清單裡標「⏰ 該複查了」，
刪不刪由你按。

### 書籤管理頁與設定頁

索引頁上方的「🔖 書籤管理 →」會開 `out/sessions/bookmarks.html`，那裡列出**所有 session**
的書籤（session 頁上那個面板只列當頁的），可以：

- 用**關鍵字**搜（備註、對話摘要、類別、對話標題、專案都吃得到）
- 只看「**⏰ 該複查了**」的
- 按**類別**篩
- 換排序：最近加入／最早加入／**快到期的先**（沒設提醒的一律排最後）
- 直接編輯或移除（移除後有「復原」，不會跳確認框）

⚠ **跳轉的連結是用 session id 現算的，不是書籤存的那個網址。** 輸出檔名含本地時間與專案名，
改專案名或換時區就全變；用 id 重算才跳得回去。那一場**不在這次輸出裡**時（還沒重建、
已刪除，或書籤是從別台匯進來的），該列會明講「⚠ 不在這次的輸出裡」並且**不給連結**
——與其給一個看起來正常、點下去卻是 404 的連結，不如講清楚。

管理頁右上的「⚙ 設定」是 `out/sessions/settings.html`：

- 「提醒我複查」的**預設值**（出廠是半年）。改了只影響**之後**新加的書籤。
- **類別管理**：改名、合併、刪除、排序。
  **改名會連動**——所有用到舊名的書籤一起改；改成一個已經存在的名字就是**合併**這兩類。
  刪除會把那些書籤的類別清空，但**留一顆「復原」**，訊息也會講清楚影響幾筆。
  ⚠ 要**新增**類別不用來這裡，加書籤的小視窗裡按「＋ 新類別」就好。

這兩頁都是純前端的空殼：書籤在瀏覽器裡，建置時看不到任何一筆，內容全由頁面自己讀出來。

### ⚠ 書籤存在瀏覽器裡，記得匯出

書籤存在 `localStorage`，也就是**只在這台機器的這個瀏覽器裡**——一次「清除瀏覽資料」就沒了。
**真正的備份是匯出的 JSON**，所以匯出鈕就放在書籤面板上，存完馬上看得到
（管理頁與設定頁下方也各有一份）。兩顆：

| 鈕 | 內容 | 什麼時候用 |
|---|---|---|
| **⬇ 完整備份** | 含每筆的 120 字**對話摘要**與自動標題 | 自己留著、換機還原 |
| **⬇ 只匯書籤** | **拿掉對話摘要與自動標題**，保留你自己寫的備註 | 要給別人看的時候 |

備註**不會**被遮——那是你自己知情打進去的字，而你按的是「備份」；有損的備份是壞掉的備份。
路徑也不會帶出 `C:\Users\<你的名字>\`：**匯出前每一個路徑都會再驗一次形狀**，
只有「相對 `out/` 的 `sessions/…`」留得下來，其餘一律丟掉（那個路徑本來就是可以用
session id 重算的快取）。

⚠ **從別人的檔匯進來的書籤，自訂標題會被當成自動標題遮掉。**
「這個標題是我自己取的」這件事只有**這台機器上真的有那份輸出**時才確認得了，
所以匯入時一律不採信檔案裡的說法——寧可多遮，不可以少遮。
到那場對話頁開一次書籤，標記就會刷回來。

匯入一律**合併**，不會覆蓋掉這台已經有的書籤：

- 同一筆撞到時，**留比較新的那個**（比的是「最後修改時刻」）。
- ⚠ 兩邊的**備註或類別都有值而且不同**時，比較新的那份放在欄位裡，
  **舊的那份會接在備註後面**（標「合併時保留的另一份值」）——不會有東西無聲消失。
- ⚠ 匯入檔**沒有時間戳、或時間戳壞掉**時，那筆一律算「時刻未知」而**不是「剛剛」**。
  這樣同一份檔案匯入兩次結果一樣，舊備份也不會反覆把你後來的編輯壓回去。
- 檔案裡的內容會先驗形狀（欄位型別、間隔、到期日）；認不出來的那幾筆會略過並在下方講出筆數。

匯出檔名是 `asv-bookmarks-<日期>.json`，`.gitignore` 已經先擋了（避免順手 commit 進版控）。

**設定（含類別清單）也在匯出檔裡**，理由和書籤一樣：只在 `localStorage` 裡＝清一次就沒了。
匯入時**類別清單取聯集**（清單只增不減），而「提醒我複查的預設值」這種單選偏好
**以這台為準**——那是你在這台刻意選過的。

### ⚠ 如果書籤資料壞掉了

`localStorage` 裡那份資料要是壞了（手改過、舊版留下的、或外部原因），
頁面**不會**把它當成「沒有書籤」——那樣下一次隨手加一筆就會把還救得回來的東西蓋掉。
它會停掉所有寫入、講出「讀不到現有的書籤」，並給一顆「**⛑ 匯出原始資料**」
把那串原始文字原樣存成檔案，讓你用文字編輯器救。

### 開著好幾個分頁

四個頁面（對話頁、索引頁、管理頁、設定頁）讀寫的是**同一份**資料。
在其中一頁改了什麼，其他已經開著的分頁會跟著重畫。
如果同一筆書籤剛好在兩個分頁同時編輯，後存的那次**不會**把對方寫的備註蓋掉——
兩邊都會留著，並在訊息列告訴你去看一下。

⚠ 書籤認的是 **session id ＋ 該輪的時間戳**，不是檔名。輸出檔名含本地時間與專案名，
改專案名或換時區會讓檔名全變——身分不綁檔名就是為了這個。
